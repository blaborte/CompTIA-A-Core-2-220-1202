Scenario A: The Disappearing Network Drive 🛡️

A user can no longer access their network drive. They can browse the internet. You suspect a recent Windows update reset the firewall profile.

You connect to their Windows 10 workstation via a remote command prompt.

Question 1: Initial Network Profile Check

You suspect the profile reset from "Private" to **"Public"**. What command utility can you use to quickly view the current network connection profiles?

Hint: You need a command to view connection properties, not IP details.
  • Possible commands: Get-NetConnectionProfile (PowerShell)
  • Possible commands: netsh interface show interface

Question 2: Identify the Firewall Utility

Result: The network profile is set to **Public**. You need to change it back to **Private**. Which utility is designed for managing Windows Firewall settings, including network profiles?

Hint: This utility manages configuration of network interfaces, protocols, and the firewall.
  • Possible commands: netsh (Network Shell)

Question 3: Verify the Fix (Port Connectivity)

Fix: You used the correct utility to switch the profile back to **Private**. **Verification:** How can you verify from the command line that the server is now reachable on the **SMB port (445)**?

What command utility should you use to test connectivity to the target server on a *specific* port (445)?

Hint: You need a tool that can attempt a connection to a port, not just send an ICMP echo request.
  • Possible commands: telnet server_ip 445
  • Possible commands: Test-NetConnection -Port 445 (PowerShell)

Scenario A Complete! ✅

Summary of Actions:

  • Check Profile: Used netsh interface show interface to confirm the profile was 'Public'.
  • Fix Profile: Used netsh to change the profile back to 'Private'.
  • Verify Port: Used telnet to test connectivity to the server on the SMB port (445).
